# MAC.BID historical acquisition analytics — next lane
Status: design and observed-inventory baseline; no production scoring change. 2026-11-26.

## Problem and scope
The current scoring engine correctly labels estimated current all-in cost and provisional stated-retail ceilings, and market valuation supplies exact external pricing. It lacks longitudinal MAC.BID closing-price distributions and arrival rates. Build a generic historical layer across all hunt profiles, not an ice-maker-only feature. Preserve existing exact-model compatibility, condition gates, external market-value authority, location restrictions, and private/public boundary. Never auto-bid.

## P0 — observations and outcome reconciliation
- Introduce an append-only, compact versioned public observation store, dedupe by source snapshot/run and stable auction_id + lot_id; timestamps UTC with actual observation time and original source time for fallback. Track location, public product identifier/identity confidence, title, condition, observed hammer, bidder counts, close time, fee/tax policy version and source URL. Treat fallback republishing as stale, not new arrivals. Retain at least 90 days prospectively with a bounded archival strategy; define retention/size limits and no personal data. Never store account state, bidder identity, headers, cookies, credentials, private user bids or watchlists.
- Verify official public past auction page contract: https://www.mac.bid/past-auctions/86418 shows explicit “Won for” and “Not Sold”; discover supported public pagination and exact lot links using normal browser navigation, not private interfaces. Current candidate auction IDs 102463, 102641, 103159 could not be fetched through current web read; do not assume absence means sold. Respect rate limits and stop on access restrictions. Backfill eligible San Antonio auctions with auditable coverage; target 90 days initially, extend only if available. No guessing hidden IDs or bypassing controls.
- Separate statuses observed_open, missing_unresolved, closed_sold_verified, closed_unsold_verified, canceled_verified. Store final hammer only on explicit sold evidence, verified close time, source reference and retrieval time. Avoid converting missing/zero bids into sales. Reconcile soft-close changes and re-listed lots; auction+lot identity and exact product grouping are different keys.
- Reuse scoring.estimated_post_tax_total with fee schedule applicable to location/time; distinguish estimated total from actual invoice. Unknown historical fee schedule is flagged; never call estimate an invoice. Add reconciliation tests for duplicate snapshots, unsold, canceled, zero/missing price, stale fallback and soft close.

## P1 — history, comparable cohorts and backtesting
- Materialize exact model/ASIN + condition + location cohorts, then explicitly labeled broader comparable families only where product specifications justify pooling. Report sample sizes, verified outcomes, unresolved count, observation-window coverage, sold P25/P50/P75/P90, unsold rate, arrival counts and time between arrivals. Distinguish one-time duplicates, repeated inventory, and actual new lots. Show condition separately; avoid pooling manual-fill and direct-refill ice makers or different variants.
- For chosen all-in budget, report empirical fraction of verified outcomes within budget (not bidder win probability), uncertainty interval, recency and coverage. Use minimum sample/coverage gates (initial proposal 20 comparable verified sold outcomes, 30 days coverage; tune with validation); otherwise display insufficient data, not synthetic precision. Distinguish probability of qualifying supply from probability of price below budget conditional on listing. Model lead-time bid changes using only snapshots before outcome; include censoring and data gaps.
- Walk-forward replay by event time, train on outcomes available before prediction, evaluate future auction cohorts; group relists/duplicate identity to prevent leakage; compare against current retail-ratio baseline and current-price baseline. Report calibration, price MAE/quantile coverage, recommendation error, missed opportunities and sample coverage. No future observations or final prices in prediction features.
- Preserve separate user value ceiling and auction-market expectation. History may inform patience and expected price, not override exact verified retail, condition, safety, fit or budget. Invert applicable premium/lot fee/tax with conservative rounding and bid increments. Add adapter/pickup/repair allowance as local acquisition-cost inputs; no private preference uploads.

## P2 — all-hunt UI and acceptance
- Per hunt: observed arrival frequency and coverage, historical closing-price distributions, current all-in vs typical close, exact versus comparable sample and confidence, price below target, recommended wait/bid/pass with reasons. Per product: timeline of actual bids/verified final outcome, lot source links, sample counts and condition. Missing outcome or insufficient evidence is obvious.
- Pilot ice makers, then locks, doorbells, projectors, solar, and all remaining profiles using common schema. Do not hardcode assumptions from one category. Keep fixed-price external inventory separate.
- Acceptance: reproducible historical ingest with evidence and deduplication; actual closed-lot fixtures (sold/unsold) plus unresolved fixture; chronology-safe backtest and documented sample coverage; user-facing results tied to real evidence; no regression of current live catalog; production integration only after review. No new private GitHub Actions, no authenticated scraping or user-specific public data. Use existing public-source-only scraper and existing authorized execution route.

## Handoff
Start with official past-auction discovery and recover expiring public artifacts, then implement persistent observation/outcome schemas, tests, and first pilot. This PR intentionally does not deploy or change ranking, and the baseline contains no verified final ice-maker price labels.
